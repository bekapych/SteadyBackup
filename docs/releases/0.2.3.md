# SteadyBackup 0.2.3

Дата: 22.11.2026.

## PostgreSQL: Dump custom и SQL plain

Для источника PostgreSQL добавлен выбор формата выгрузки каждой базы:

* `custom` — собственный формат `pg_dump -Fc`, файл `<база>.dump`, восстановление через `pg_restore`.
  Этот формат используется по умолчанию, в том числе для заданий, созданных прежними версиями.
* `plain` — текстовый SQL-скрипт `pg_dump -Fp`, файл `<база>.sql`, восстановление через `psql`.
  В отличие от уже сжатого Dump custom, текстовый SQL сжимается 7-Zip с настройками задания.
* Проверка `verify` чтением оглавления `pg_restore --list` выполняется только для `custom`.
  Для `plain` она не применяется: `pg_restore` не читает SQL-скрипты.

## Очистка журнала запусков

На вкладке «Журнал» добавлена кнопка «Очистить журнал…». Операция доступна только администратору
и выполняется после подтверждения в GUI. Очищаются видимый журнал запусков (`history.jsonl`) и итоги
последних запусков в списке заданий. Резервные копии, задания и текстовые файлы `logs\steady.log*`
не удаляются и не изменяются.

## Совместимость и ограничения

* Старые JSON-задания без поля `format` читаются как `custom`; ручная правка настроек не требуется.
* Выбор формата PostgreSQL не меняет имена наборов, отдельные архивы баз и правила ротации.
* Для SQL plain не выполняется проверка через `pg_restore`; восстановление такого дампа производится через `psql`.
* Очистка журнала относится только к видимой истории запусков и не заменяет текстовые журналы службы.
