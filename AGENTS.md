# SteadyBackup — инструкции для ИИ-агента разработчика

Этот файл читается агентом перед любой работой в репозитории. Разбор текущего состояния кода
и очередь задач — в `docs/REVIEW.md`. Архитектура — в `docs/ARCHITECTURE.md` (частично устарела,
см. раздел «Документация» ниже). Примеры заданий и CLI — в `examples/jobs.md`.

## 1. Что это за проект

Резервное копирование для Windows: файлы, файловые базы 1С, MS SQL, ВМ Hyper-V →
7-Zip → локальная папка / SMB / SFTP / WebDAV / Google Drive, с ротацией и уведомлениями.

```
Cargo.toml                    workspace (edition 2021, resolver 2)
crates/steady-core/           библиотека: модели, конвейер, источники, назначения, расписание
  src/job.rs                  модель задания (serde, tag = "type", snake_case)
  src/pipeline.rs             run_job: источник → staging → 7-Zip → назначения → ротация
  src/source/                 files, onec, mssql, hyperv (+ hyperv.ps1, hyperv-restore.ps1)
  src/destination/            трейт Target; fs (локально/SMB), sftp, webdav, gdrive
  src/state.rs                каталог файлов для инкр./дифф. копий
  src/store.rs                задания, журнал history.jsonl, метки планировщика
  src/resources.rs            «Хранилища» и «Подключения» (общие для заданий)
  src/secret.rs               DPAPI: значения вида dpapi:<base64>
  src/notify.rs               e-mail (lettre) и Telegram
  src/schedule.rs             расписания, next_after()
crates/steady-service/        бинарник steady.exe
  src/main.rs                 CLI (clap)
  src/engine.rs               очередь, один исполнитель, планировщик (тик 15 с)
  src/ipc.rs                  именованный канал \\.\pipe\SteadyBackup, построчный JSON
  src/service.rs              служба Windows (LocalSystem), install/uninstall
gui/                          Qt 6 Widgets, C++17, CMake; только клиент IPC
tools/                        install.ps1, ipc.ps1, shot.ps1
```

Данные службы: `%ProgramData%\SteadyBackup` — `jobs\`, `state\`, `storages\`, `connections\`,
`gdrive\`, `work\`, `logs\`, `history.jsonl`, `scheduler.json`, настройки уведомлений.

Не трогать и не читать без необходимости: `target\` (2,5 ГБ), `build-gui\`, `dist\`.

## 2. Сборка и проверка

Целевая платформа — только Windows (x64). Служба, DPAPI, SMB и IPC вне Windows не работают;
`steady-core` должен продолжать компилироваться вне Windows там, где это уже так (`cfg(windows)`).

```
cargo build --release
cargo test --workspace
cargo clippy --workspace --all-targets
cmake -S gui -B build-gui -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/msys64/ucrt64
cmake --build build-gui
```

Всё сразу, вместе с MSI: `build.cmd` в корне (или `tools\build.ps1 [-SkipTests]`). Сценарий собирает
службу и GUI, кладёт GUI в `dist\gui`, комплект для установщика в `dist\payload` и MSI в `dist\`.
Журналы шагов и итог — в `build-logs\`. Сценарий ничего не устанавливает и службу не трогает.

Ручная проверка без установки службы:

```
steady --data-dir <временный каталог> run job.json        выполнить задание
steady --data-dir <временный каталог> console             планировщик + IPC в консоли
tools\ipc.ps1 '{"cmd":"list_jobs"}'                        запрос к работающей службе
```

Правила:

* Для экспериментов всегда указывай `--data-dir` во временный каталог. Не пиши в
  `%ProgramData%\SteadyBackup` и не меняй задания пользователя.
* `tools\install.ps1`, `steady install` и `steady uninstall` меняют систему (служба, Program Files,
  реестр). Запускай их только по прямой просьбе пользователя.
* Не запускай реальные резервные копии против чужих серверов, баз 1С, SQL Server и ВМ.
  Для тестов создавай локальные каталоги и назначение `local`.
* Не утверждай, что что-то «проверено», если ты это не запускал. Пиши, что именно выполнено
  и с каким результатом.

## 3. Принятые в коде соглашения

Rust:

* Ошибки — `anyhow::Result`, контекст через `.context()` / `.with_context()`, прерывание через `bail!`.
* Журнал — `tracing` (`info!`, `warn!`, `error!`). `println!` только в CLI-командах `main.rs`.
* Сообщения об ошибках, журнал и комментарии — на русском. Идентификаторы — на английском.
* Комментарии объясняют «почему», а не «что». Док-комментарии `///` на полях моделей обязательны:
  они заменяют описание формата заданий.
* Модели — `serde`, перечисления с `#[serde(tag = "type", rename_all = "snake_case")]`.
  Новые поля добавляй с `#[serde(default)]`, чтобы старые JSON-файлы заданий продолжали читаться.
  Существующие имена полей и значений не переименовывай.
* Запись файлов состояния — атомарно: временный файл + `rename` (как в `state.rs`, `store.rs::save_job`,
  `resources.rs::write`).
* Синхронный код; tokio используется только внутри SFTP (однопоточный runtime) и в IPC-сервере.
  Не превращай конвейер в async.
* Новые зависимости добавляй только при явной необходимости и говори об этом пользователю.
  Общие версии — в `[workspace.dependencies]`.
* `unsafe` только для вызовов WinAPI, с освобождением ресурсов в той же функции.

C++ / Qt:

* Собирается с `QT_NO_KEYWORDS`: используй `Q_EMIT`, `Q_SIGNALS`, `Q_SLOTS`.
* Все строки интерфейса — через `tr()`, на русском. Ключи JSON — `QStringLiteral`.
* GUI не содержит бизнес-логики и не читает файлы службы: всё через `ServiceClient::call`.
* Новый файл исходников нужно добавить в `gui/CMakeLists.txt`.
* Цвета, значки и таблица стилей — только в `gui/src/theme.cpp`. В остальном коде не вызывай
  `setStyleSheet` и не пиши цвета числами: пояснения — `theme::markHint`, результат проверки —
  `theme::setState`, значки — `theme::icon`. Тема следует за светлым и тёмным режимом Windows.

## 4. Инварианты, которые нельзя ломать

1. **Состояние инкремента** (`JobState`) сохраняется только после успешной отправки копии.
   Не сохраняй его раньше и не сохраняй при полном провале отправки.
2. **Отправка атомарна**: объект появляется в назначении под итоговым именем только целиком
   (`<имя>.partial` → переименование). Ротация пропускает `.partial`.
3. **Имя набора**: `<safe_name(job)>_<YYYYmmdd>_<HHMMSS>_<full|inc|diff>[.7z[.NNN]]`.
   На этом формате держится ротация (`pipeline.rs::parse_set`). Меняя формат, сохраняй разбор старых имён.
4. **Ротация** удаляет только объекты, имя которых разобрано как набор этого задания.
   Никогда не удаляй из назначения ничего другого.
5. **Ошибка одного назначения не отменяет остальные**; итог «успешно с предупреждениями».
6. **Секреты**:
   * в файлах на диске — только `dpapi:...`; открытый текст шифруется при сохранении (`protect_secrets`);
   * в ответах IPC, которые видит GUI, — только маркер `dpapi:stored`; при сохранении маркер
     заменяется сохранённым значением;
   * секреты не пишутся в журнал, в `history.jsonl`, в тексты ошибок и уведомления.
7. **IPC**: любая новая команда по умолчанию доступна только администраторам. В список
   `read_only` в `ipc.rs::dispatch` добавляй команду, только если её ответ не раскрывает
   секреты, пути к учётным данным и содержимое заданий.
8. **Паника в задании не роняет службу** (`catch_unwind` в `engine.rs`). Не добавляй `unwrap()`
   на данных из файлов, сети и внешних процессов.
9. **Совместимость данных**: существующие `jobs\*.json`, `state\*.json`, `storages\*.json`,
   `scheduler.json` должны читаться после обновления без ручной правки.

## 5. Безопасность — обязательные правила

Служба работает от SYSTEM и запускает внешние программы, поэтому:

* Любой путь к исполняемому файлу, приходящий из задания (`platform_exe`, 7-Zip), — это запуск
  кода от SYSTEM. Не добавляй новых полей такого рода без проверки, что файл недоступен для записи
  обычным пользователям.
* Не добавляй передачу паролей через аргументы командной строки. Существующие случаи
  (7-Zip `-p`, `sqlcmd -P`, 1С `/P`, `/UC`) — известный долг, см. `docs/REVIEW.md`.
* Не ослабляй SDDL канала, проверку администратора и `reject_remote_clients`.
* Не вставляй в SQL и в PowerShell-сценарии значения из задания без экранирования
  (`quote_ident`, `quote_str` в `mssql.rs`; параметры сценариев передаются аргументами, не подстановкой в текст).
* Встроенный OAuth-клиент Google в `gdrive.rs` не менять и не выносить в журналы и документы.
* Не коммить и не выводи в ответах содержимое `%ProgramData%\SteadyBackup`, токены, пароли,
  refresh-токены, ключи SSH.

## 6. Как работать над задачей

1. Прочитай связанный код целиком (файлы небольшие), а не только место правки.
2. Бери задачи из `docs/REVIEW.md` по порядку приоритета, одну за раз. Не смешивай в одном
   изменении исправление и рефакторинг.
3. Сначала тест, воспроизводящий проблему, затем исправление. Логику без WinAPI и сети
   (расписание, ротация, инкремент, разбор имён, манифест) покрывай модульными тестами
   в том же файле (`#[cfg(test)] mod tests`), с временными каталогами.
4. Минимальный дифф: не переформатируй нетронутый код, не переименовывай без нужды.
5. После правки: `cargo test --workspace` и `cargo clippy --workspace --all-targets`.
   Если менялся GUI — сборка CMake.
6. Если меняется формат задания, IPC-команда или CLI — обнови `examples/jobs.md`
   и `docs/ARCHITECTURE.md` в том же изменении.
7. Закрыв задачу из `docs/REVIEW.md`, отметь её там как выполненную (дата, что сделано).
8. В отчёте пользователю: что изменено, какие проверки запущены и их результат,
   что не проверено (например, «на реальной ВМ Hyper-V не запускалось»).

Спрашивай пользователя перед тем, как:

* менять формат файлов данных несовместимо или мигрировать данные;
* менять поведение ротации, планировщика или прав доступа IPC;
* добавлять зависимости, менять лицензию, трогать установку службы;
* удалять файлы вне `target\` и временных каталогов.

## 7. Документация

`docs/ARCHITECTURE.md` местами описывает планы, а не код. Фактическое состояние:

| В документе | В коде |
|---|---|
| SQLite | JSON-файлы в каталоге данных |
| `reqwest`, Digest для WebDAV | `ureq`, только Basic |
| хеш BLAKE3 в каталоге файлов | только размер и mtime |
| `7za.exe` в комплекте | ищется рядом с программой или в `Program Files\7-Zip` |
| проверка/завершение сеансов 1С | передаётся только `/UC` |
| лимит параллельных заданий | один исполнитель, задания строго по очереди |
| VSS, pre/post-события | не реализовано |
| — | раздел «Хранилища» и «Подключения» (`resources.rs`) в документе не описан |

При расхождении документа и кода верь коду и исправляй документ.

## 8. Репозиторий

На момент разбора (2026-11-10) в каталоге нет git. Если пользователь попросит завести:
`.gitignore` должен исключать `target/`, `build-gui/`, `dist/`, `*.log`, `*.log.*.gz`.
Сообщения коммитов — на русском, в повелительном наклонении, одна логическая правка на коммит.
